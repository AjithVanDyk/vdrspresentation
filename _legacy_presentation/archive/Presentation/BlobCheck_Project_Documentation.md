# BlobCheck Project Documentation

## Overview
- Goal: verify that Azure Blob Storage and the SQL Server file catalog remain in sync for Contracts Shipping records.
- Location: `G:\Interns\Ajith Srikanth\BlobCheck`.
- Deliverables: CSV exception reports (`missing_in_sql.csv`, `missing_in_azure.csv`, path variants, duplicate summaries) that highlight mismatches between systems.
- Status: utility scripts run on demand; `verify_vdrs_v1.py` is the current enhanced version, `verify_vdrs.py` kept for quick comparisons.

## Technology Stack
- Python 3.x
- Azure SDK: `azure.storage.blob.ContainerClient`
- SQL connectivity: `pyodbc` (ODBC Driver 17 or 18 for SQL Server)
- Standard library: `csv`, `os`, `urllib.parse`, `collections`, `re`

## Project Files
| File | Purpose |
| --- | --- |
| `verify_vdrs.py` | Baseline script that lists Azure blobs, compares with SQL records, and exports two mismatch reports. |
| `verify_vdrs_v1.py` | Enhanced script with dynamic driver detection, case-sensitive comparisons, project/container extraction, and richer CSV output. |
| `missing_in_sql*.csv` | Azure files that are not found in SQL (`*_paths` variants include normalized path lists). |
| `missing_in_azure*.csv` | SQL records that do not have a matching blob in Azure. |
| `duplicates_in_sql.csv` | Duplicate records detected in SQL (generated by extended tooling when duplicates exist). |

## Configuration
Both scripts read endpoints and credentials from constants at the top of the file:
- `AZURE_SAS_URL`: SAS token granting read/list access to the `contractsshippingfiles` container.
- `SQL_SERVER`, `SQL_DB`, `SQL_USER`, `SQL_PASSWORD`: SQL Server connection details.
- `FILES_TBL` (and `CNTRS_TBL` in v1): database tables to query.
- `OUT_DIR`: output directory for CSV exports (defaults to the project folder).

> **Security note:** The current code contains plaintext credentials and SAS tokens for development convenience. Move these values to environment variables or secure secrets storage before production use.

## Script Breakdown
### `verify_vdrs.py`
1. Connects to Azure using the provided SAS URL and builds a dictionary `{normalized_path: {BlobPath, Size}}`.
2. Connects to SQL Server, queries `ContractsShippingContainerFiles`, and builds `{normalized_path: {FileID, BlobPath}}` using `AzureFilePath`, `AzureFileID`, or `FileName`.
3. Normalizes paths using `norm_path()` (lowercase comparison, slash normalization, URL stripping).
4. Computes two sets:
   - `missing_in_sql` – blobs present in Azure but absent from SQL.
   - `missing_in_azure` – entries present in SQL but missing from Azure.
5. Writes the sets to CSV and prints a summary.

### `verify_vdrs_v1.py`
Enhancements on top of the baseline script:
- `pick_sql_driver()` selects ODBC Driver 18 first, then 17, reducing connection issues on newer systems.
- `norm_key_keepcase()` keeps original casing (important for projects that rely on case-sensitive organization).
- `project_from_blobpath()` extracts the probable project identifier while skipping generic prefixes (e.g., “Containers”, “Documents”).
- `fetch_sql_maps()` returns both file rows and a map of project references to container numbers for richer reporting.
- Generates a detailed `missing_in_sql.csv` with columns: `ProjectNo`, `ContainerNos`, `AzureBlobName`, `AzureBlobPath`, `Size`, `LastModified`.
- Prints a preview of the first 30 missing entries directly in the console.

## Running the Scripts
1. Install dependencies:
   ```bash
   pip install pyodbc azure-storage-blob
   ```
2. Ensure an appropriate SQL Server ODBC driver (17 or 18) is installed.
3. Update the configuration section with valid SAS URL and SQL credentials (preferably via environment variables before running in production).
4. Execute the desired script:
   ```bash
   python verify_vdrs_v1.py
   ```
5. Review console output for summary statistics and open the generated CSV files in Excel or a BI tool for further triage.

## Error Handling & Logging
- Missing drivers raise a clear `RuntimeError` (`verify_vdrs_v1.py`).
- Connection errors bubble up with informative messages from `pyodbc`.
- CSV writing guarantees the output directory exists (`ensure_outdir()`/`write_csv()`).
- Console preview (v1) offers immediate visibility into out-of-sync records.

## Best Practices & Next Steps
- **Credential hygiene:** externalize SAS and SQL secrets before automation.
- **Automation:** schedule `verify_vdrs_v1.py` via Task Scheduler or Azure Automation to run nightly and email the CSV results.
- **Alerting:** integrate with Power BI or send summaries to Teams/Slack for rapid response.
- **Data clean-up:** use `ContainerNos` and `ProjectNo` columns to coordinate with operations teams when moving or renaming blob folders.
- **Extensibility:** add duplicate detection and blob metadata validation (content type, checksum) if required.
